# Hooks that enforce this skill

`~/.claude/settings.json` runs these scripts from the merged copy in `~/.claude/skills/claude-worktree/hooks/`. Each command is a no-op until that file exists, so edits on `claude` take effect only after the user merges.

| Event | Script | Effect |
|---|---|---|
| SessionStart | `session-start.sh` | Prints first the hot sheet (`kb hot`; nothing if kb fails), then git state of the project and skills repositories (runs `ensure-worktree.sh`; a skills mirror and a `claude.worktree=false` repository are reported as such), the skill specialisation map, the pointer `kb ls host/<hostname>` and the failures of `kb probe --cat host/<hostname> --budget 3 --stale 30d` (facts without a probe are not listed), the handoff's `kb ls` topics and open items (`kb render --open`) from the `docs/kb` beside it, or its §0 when there is no `docs/kb`, `scripts/kb` fails or the schema is too new (exit 3); a project with only a `docs/state.json` still gets `scripts/state.sh render` (outside a repository or with cwd `$HOME`: the global `~/.claude/skills/docs/`), a `MISSING:` line when the global handoff or the home memory index is absent or empty, and the project's `.claude/hooks/session-start.sh` output |
| PreToolUse Edit, Write, MultiEdit, NotebookEdit | `guard-edit.sh` | Blocks edits outside the allowed locations in SKILL.md, Claude's settings and `~/.claude/CLAUDE.md` (and their chezmoi copies), the edit-allow file, and anything in a skills mirror |
| PreToolUse Bash | `guard-bash.sh` | Lexes the command (`git-write-dirs.py`, read on stdin): quoted text and commands sent over ssh/docker/kubectl are not local; `$(…)` and backticks inside double quotes, here-documents fed to a shell, `bash -c`, `su -c`, `flock -c`, `script -c`, `time`, `find -exec`, `xargs` and `parallel` are looked into. Blocks: Bash commands that read or edit a store file directly (`docs/state.json`, anything under `docs/kb/`; `raw-store-read.py`) unless run by `scripts/kb`, `state.sh`, `check.sh`, `git` or a metadata command (`ls`, `stat`, `wc`, `cd`; paths are normalised first: `//`, `/./`, `x/../`), and also a recursive `grep`/`rg`, `cat` or `find -exec` on a parent directory of `docs/kb` (`docs`, `~/.claude/skills/docs`, `docs/*`), `git show|cat-file|grep` of `<rev>:docs/kb/...`, and any non-metadata command after a `cd` into `docs/kb` (`cd docs/kb && ls` passes); `git push`; bare, untagged or destructive stash (`git stash`, `stash pop`, `stash push` without `-m`, `stash drop`, `stash clear`); `sudo`, `su`, `pkexec`, `run0`, `doas` (flag-only probes such as `sudo -n true` pass); git aliases defined with `-c alias.*` or `--config-env`; git writes (commit, merge, pull, reset, checkout, worktree remove/move/prune, …) in a main checkout that has a `claude` branch, in a skills mirror, or in a `claude.worktree=false` repository (there only staging: `git add`, `rm`, `mv`); and ref rewrites of any branch other than `claude*` or of tags from any directory (`branch -f/-d/-m`, `update-ref`, `tag -d/-f`, `fetch . x:<branch>`, `symbolic-ref`). Then runs the project's `.claude/hooks/pre-bash.sh`. If the parser cannot run (no python3, error, huge command) it falls back to conservative regex checks and blocks rather than allows. Known limits: a command name held in a variable, text other than echo/printf/cat piped into a shell, and shell function bodies (checked where defined) |
| PreToolUse Edit, Write, MultiEdit, NotebookEdit, Bash | `skill-gate.sh` | Blocks an action until the skills it needs have been invoked in this session (after the last compaction; a subagent's own transcript for subagent calls). Gates are tab-separated lines (tool regex, target regex, skills, reason) in `claude-worktree/skill-gates` and the project's `.claude/skill-gates`; edit targets are matched as repository-relative paths, Bash targets as the command; editing `docs/kb/<topic>.json` needs `instruction-layer`. A skills field may hold `agent:<subagent_type>` (`agent:advisor`): satisfied by an `Agent` tool call with that `subagent_type` in the main transcript after the last compaction and after the last human prompt (`"origin":{"kind":"human"}`; if none is found, the compaction boundary only); a subagent's call is judged by its parent's transcript. The block says to consult the agent and retry. This repo's `.claude/skill-gates` requires `agent:advisor` (once per user message) for `SKILL.md`, `references/*.md`, `agents/advisor.md`, `claude-worktree/hooks/`, `claude-worktree/skill-gates`, `.claude/skill-gates`, `scripts/kb`, `scripts/check.sh` and `scripts/shellast.py`; `git commit` and `docs/kb` data are not gated |
| PostToolUse Skill | `log-skill.sh` | Appends each skill invocation to `~/.claude/skill-usage.jsonl`; the gate appends its blocks there too |
| Stop | `stop-check.sh` | Blocks the end of a turn while a `claude` worktree has uncommitted changes, while it has non-merge commits (not on the user's branch) since its `docs/HANDOFF.md`, `docs/state.json` or `docs/kb/setup.json` last changed (only those three count: `setup.json` holds items, decisions and pitfalls; a commit that touches only `host.json` or `games.json` does not clear the block), while the turn read system state and recorded no fact (`explored-facts.py`: Bash state commands, Bash/Read/Grep/Glob on `/etc`, `/sys`, `/proc`, `/usr/lib` and similar, in the main transcript since the last typed prompt and in subagent transcripts from the same time; an Edit, Write or writing command on a `references/`, `SKILL.md`, `HANDOFF.md`, `docs/kb/` or memory path, or `kb add|set|close|link|ref|mv|edit|supersede|import-*`, counts as recorded; `kb probe`, `kb ls|get|find|search|links` and any kb command with `-h`/`--help` count as neither (a failed kb command is not checked); any change to a matching path counts, so the hook cannot tell whether the right fact was recorded), or while the project's `.claude/hooks/stop-check.sh` reports something; adds a `reflect:` line (`reflect.py`, same transcript window and subagents) when the main transcript shows 6 or more lookups (Read/Grep/Glob, `kb ls|find|get|links|search`, Explore agents, read-only Bash) or a kb miss (exit 1, "not recorded") was followed by a kb hit, and no `kb set` or `kb add --type warning|context|fact` ran in the turn or its subagents (subagents are read only for such writes); the line carries the lookup count and result characters, and each block is logged to `~/.claude/skill-usage.jsonl` as `reflect-block`; allows the second attempt (`stop_hook_active`) |
| PreCompact | `stop-check.sh --warn` | Prints the same problems without blocking |

A project adds its own rules with executable scripts in `<repo>/.claude/hooks/` (`pre-edit.sh`, `pre-bash.sh`, `stop-check.sh`, `session-start.sh`), committed on `claude`. They are called with the main checkout and worktree paths as arguments (`pre-edit.sh` also gets the target path; it runs before the allowlist, so it can block paths inside a worktree). Exit 2 blocks. A project's git pre-commit hook lives in the repository (for example `scripts/git-hooks/pre-commit`) and is enabled with `git config core.hooksPath <path>`, which applies to the user's commits too.
